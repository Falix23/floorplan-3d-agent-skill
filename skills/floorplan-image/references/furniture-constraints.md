# 家具还原：方向、使用关系与接触约束

没有穿墙、外包框重合、2D/3D使用同一个旋转值，都不能证明朝向正确。矩形旋转180度后外包框不变，沙发仍可能背对茶几。源图还原必须记录下列证据，并在实际画面中复核，不能只写交付说明。

## 源图方向

放大局部，找枕头和床头板、沙发靠背/扶手、柜背/柜门使用面，再确定本体框和旋转。投影、地毯、邻近椅子不并入本体。

当前参数化床、座椅和柜子的0度统一：背面/床头朝图上方（局部-Y、3D局部-Z），正面朝下（局部+Y、3D局部+Z）。旋转是屏幕顺时针：

| rot | 背面/床头 | 正面/床尾 |
| --- | --- | --- |
| 0 | 上 | 下 |
| 90 | 右 | 左 |
| 180 | 下 | 上 |
| 270 | 左 | 右 |

将从原图确认的正面向量写入orientationConstraint.front，不要从已填rot反算向量再冒充源图证据。observed表示特征可见；inferred表示按相邻空间或使用关系推定，须单列待复核；unknown不算识别完成。released仅表示用户已主动修改，不能在初次还原时用来绕过证据。

```json
{
  "id":"I1", "type":"sofa", "name":"客厅沙发",
  "bboxPx":[100,400,340,480], "rot":180,
  "orientationConstraint":{
    "status":"observed", "front":[0,-1], "feature":"backrest",
    "maxAngleDegrees":5, "evidence":"原图下侧细长靠背与扶手可见，座面朝上侧茶几"
  },
  "facingTarget":{"targetId":"I2", "maxAngleDegrees":60,
    "evidence":"原图茶几在座面前侧"},
  "placement":{"mode":"wall", "roomId":"R1", "edgeIndex":2, "side":"back",
    "gapPx":0, "maxAdjustPx":2, "evidence":"靠背与南侧实体墙内边相接"}
}
```

Python和浏览器均拒绝与方向证据矛盾的方案，不自动翻转，也不用平移掩盖。看不清时记录具体不确定项，不能仅凭OCR名称、类别默认方向或美观猜测。

## 使用关系

为沙发/单椅记录面向哪台电视或哪张茶几，为桌椅记录对应桌面/书桌。facingTarget引用本层ID，正面须落在目标方向的指定角度内（必须小于90度）。环桌椅可以座面朝桌心作为关系推定，须注明靠背像素不清；不能写成逐像素观测。不要为通过检查移动茶几/电视，先复查原图和旋转。

不引用另一层同名家具或不相关目标。床和柜子的使用面需与出入空间一致，但不能凭常识推翻清晰的原图特征。

## 接触与间隙

明确靠墙的床头、柜背、沙发靠背均填写roomId、edgeIndex、side、gap、maxAdjust和evidence。在像素观测中使用gapPx/maxAdjustPx，转换后为mm。校正只沿指定边法线小范围平移，不改变尺寸、沿墙坐标和朝向。超限回看原图，不扩大阈值。

- 原图接触：消除描边小缝；最终复核实际网格的接触误差。
- 原图留缝：保留原图gap，不强制设零。
- 独立单椅、居中沙发、分隔柜：明确placement.mode:free并写原因，不全局吸附最近墙。
- 柜体不是墙：区分柜门线与实体墙，不为贴柜子臆造墙；分隔柜可以背向另一功能区。
- 门洞、开放分区边不能提供支撑；默认只认可实体墙，不把窗洞当墙。

原图明确床头/靠背临窗时，可显式placement.support:window-plane，并有evidence和verticalVerified:false。它只对齐实际窗面投影线，支撑需由该边实际墙段和窗段覆盖，门洞仍不接受。报告须单列这些接触，不能称为“实墙贴合通过”；窗台和家具高度未标时仍未验收。不能为了绕过校验而改成窗面。

## 强制构建与验收

像素转换器默认开启以下规则；源图还原的观测和计划仍应显式保留，方便审计。基础手工设计JSON不因此被当作图片识别结果：

```json
"furnitureReview":{"required":true,"requireFacingTargets":true}
```

开启后，床、沙发、单椅、衣柜/柜体/鞋柜/书柜必须有方向证据与接触/自由摆放分类；座椅必须有面向目标。缺失、未知方向、反向或错误目标阻止构建。inferred仍检查几何方向，但在semanticReview.inferredDirections单列，不能包装成已视觉确认。手工设计和上游示例不是源图识别，不为让真实案例通过而关闭此开关。

沿用reconstruct.py from-pixels/refine/audit和plan_tools.py validate/build。多层逐层处理后组装。保存semanticReview、anchorErrorMm、支撑类型、调整前后位置及不确定项，不能以“没有穿墙”替代方向/接触验收。

对照源图局部逐件看床头/枕头、靠背、柜门和接触边。2D核对实际SVG特征；3D核对实际床头板、靠背和柜门面几何。View3D.semanticDirections()提供从这些网格部件测得的方向。结合实际网格接触间隙验收，不只比较JSON.rot或整体矩形。自定义GLB没有可核对的语义部件时需目视复核，不能声称已经通过自动部件验收。

保留修正前后HTML、实际截图和约束报告。机械校验只能检查已记录证据的一致性，不能证明Agent识别的证据本身正确，不提供未经独立标注评测的识别准确率。

## 高度与剖切显示

平面图通常不能给出柜高。缺少立面、尺寸或照片依据时，将家具高度及层净高单列为工作估计，不能称为已从原图恢复。全高墙验收时，检查实际3D网格的 `bottomMm + heightMm` 与当前层 `plan.height`，而不只检查家具的可选height字段；模板装饰件也可能改变最高点。室内柜体超出设定净高须停止验收并复查尺寸/模型，不得为画面好看任意压矮柜子或抬高层高。外部构件或有挑空的位置需另列竖向依据，不能套用普通室内结论。

每层交付全高墙对照。剖切墙仅降低墙体的显示高度，家具保持原高：衣柜2.2m高于1.2m剖切墙不表示高于2.8m实际设定墙高。剖切截图必须注明显示高度并保留全高图，不把剖切上限当作真实墙高，也不把柜高跟随剖切缩小。当前 `View3D.diagnostics()` 可读取设定净高、墙体显示上限、实际墙网格最高点及各家具实际高度；切换全高/剖切后要核对家具高度及完整JSON保持不变。

## 用户主动编辑

用户移动、旋转或改尺寸时，解除原图贴墙、方向及面向约束，保留previousWall/previousSource/previousFacingTarget历史；移动或删除目标也解除相关旧关系。新布置能撤销、完整导出、新会话导入和刷新，不重新吸回原图。不要把用户设计编辑判成识别错误，也不把已编辑方案当作原图忠实还原。
