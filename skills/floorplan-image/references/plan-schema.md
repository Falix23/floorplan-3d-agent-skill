# 完整户型 JSON v1

顶层是裸计划对象，不能仅输出家具数组。单位均为 mm，角度为度。所有数值须有限，id 用字母开头的字母、数字、下划线、连字符。

```json
{
  "schemaVersion": 1,
  "id": "case-bedroom-01",
  "title": "图片还原户型",
  "units": "mm",
  "height": 2800,
  "scale": {"status": "estimated", "evidence": "无尺寸；以床长约2000mm估计"},
  "rooms": [{"id":"R1","name":"卧室","poly":[[0,0],[4000,0],[4000,5000],[0,5000]],"mat":"wood","at":[2200,3600]}],
  "walls": [[-200,-200,4200,0,"u"],[-200,5000,4200,5200,"u"],[-200,0,0,5000,"u"],[4000,0,4200,5000,"u"]],
  "windows": [],
  "doors": [],
  "slides": [],
  "furniture": [{"id":"I1","type":"bed","name":"双人床","cx":2000,"cy":1300,"w":1800,"d":2000,"rot":0,"color":"#c9d6df","evidence":{"size":"类别先验估计","orientation":"床头朝图上方"}}],
  "uncertainties": ["门窗位置未能辨认；暂未补绘","承重属性未知","层高采用2800mm示意值"]
}
```

## 房间与墙

`rooms[].poly` 为内净地面多边形，非墙中线；凹多边形允许，不能自交。标签点 `at` 可省略，填写时必须在房间内。`counted:false` 用于不计入总使用面积的特殊区域；模板将其按飘窗台表现，普通阳台不要随意设 false。

材质可选：`wood`、`walnut`、`tile800`、`tile600`、`marble`、`antislip`、`terrazzo`、`carpet`。

`walls` 为 `[x0,y0,x1,y1,kind]`，必须 `x1>x0,y1>y0`。kind 为 `b` 承重、`e` 外墙、`n` 已知非承重、`low` 矮墙、`u` 未知。外轮廓和所有共墙只画一次。房间边界不能侵入墙厚；相邻房间可能相隔一层墙厚。

## 门窗

`windows` 为 `[x0,y0,x1,y1]` 洞口矩形；3D 将构造窗台、窗框、玻璃与过梁，当前窗台默认900mm、窗顶最高2400mm。

平开门：

```json
{"name":"卧室门","rect":[4000,3400,4240,4300],"h":[4000,4300],"c":[0,-1],"o":[-1,0],"len":900}
```

`h` 是铰点；`c` 是从铰点指向关闭门扇末端的轴向单位向量，`o` 是开启后的轴向单位向量，两者垂直。`len` 是门宽，以上门关闭时由 `(4000,4300)` 指向 `(4000,3400)`，开启时指向 `(3100,4300)`。`entry:true` 表示入户门。未知开启方向时写明采用示意方向，不要称为已识别。

推拉门：`{"rect":[0,3000,200,4500],"v":true}`。`v:true` 表示洞口长轴沿 y。

**实体墙必须在门窗处断开**，不能先画整墙再放一个门来覆盖。2D 可能看似正常，3D 会有实墙堵门。窗台和过梁由渲染器生成。

## 家具与朝向

家具：`id,type,name,cx,cy,w,d,rot,color`。`w` 是未旋转模型的局部左右宽，`d` 是局部前后深；`cx,cy` 始终为中心，`rot` 为屏幕顺时针角度。

模板模型背面默认朝图上方（3D 的 -z）：床头、沙发背、柜背都采用这一方向。床 `rot:90` 表示床头朝右，`rot:180` 朝下，`rot:270` 朝左。椅子则背面按同样方式变换。

从旋转家具的图像包围盒恢复宽深时，90/270度需要交换包围盒的长宽；不能既交换尺寸又重复改变方向。非直角旋转应使用有向矩形而非轴对齐框反推。

`evidence`、`uncertainties` 等附加 JSON 字段会保留，可记录读到的尺寸、像素观测、置信度。不能把模型自评置信度当作测量精度。

## 照片家具资产

`furnitureAssets` 是可选的资产注册表，以资产 ID 为 key。家具保留目录 `type` 作为语义类别，通过可选 `assetId` 引用资产；可选 `height` 表示该实例的高度（mm），未给出时使用资产的 `defaultHeightMm`。中心、宽深与 `rot` 继续使用上面的定义。

单个资产 JSON 与注册表中的值采用同一结构：

| 字段 | 含义 |
| --- | --- |
| `id` | 有效资产 ID，与注册表 key 一致 |
| `format` | 固定为 `glb` |
| `dataUrl` | `data:model/gltf-binary;base64,` 加完整 GLB 编码；纹理须内嵌，无外部资源 URI |
| `topViewDataUrl` | 同一网格正俯视渲染的透明 PNG，`data:image/png;base64,` 编码 |
| `defaultHeightMm` | 未指定实例高度时使用的高度；估计须记录依据 |
| `provenance` | 来源及方法记录，包含 `method`、`sourceImageSha256`、`license` 等；记录模型作者/来源、照片使用条件、匹配差异、适配改动与不确定项 |

当前支持无动画、无蒙皮、无 glTF 扩展的静态三角网格；GLB 上限12MiB、三角面上限250000，俯视 PNG 上限4MiB。`prepare --material-mode preserve-pbr` 保留3D源UV/PBR和按记录缩小的嵌入纹理；`vertex-color` 模式简化为线性顶点色。两者的2D PNG均为同几何的顶点颜色采样并输出sRGB，不保留全部细纹理或PBR光照。`alignment` 为预处理输出的轴向、源比例、归一化包围盒与面数记录，用于复核，不改变家具实例的尺寸权威。

网格本地坐标为 X 宽、Y 高、Z 深，背面朝 -Z、正面朝 +Z、底面 Y=0。预处理后的包围盒是 `[-0.5,0,-0.5]` 到 `[0.5,1,0.5]`；浏览器按实例 `w/height/d` 缩放，再按计划中心和 `rot` 放置。2D 图像从相同网格正投影产生，并使用同一宽深与旋转；不得用源照片的透视长宽替代占地。

完整计划和浏览器导出的状态须保留整个注册表及家具引用，不能仅保留资产文件路径。导入损坏或无法解析的资产时不应污染当前家具；渲染失败显示默认模型并提示。浏览器本地存储不足时，完整 JSON/HTML 是可携带备份。获取网格、制作资产与逐步验收见 [furniture-image.md](furniture-image.md)。

## 浏览器接口

`window.Floorplan.loadPlan(plan)` 导入裸计划；`exportPlan()` 返回当前几何/名称/材质/家具；`getState()` 返回包含拆墙、测量的完整状态。文件菜单导出完整状态（含 `plan`），再导入可恢复拆墙和测量。传入旧版仅家具的 JSON 会明确拒绝，不混用默认户型。

几何修改方式：文件 → 编辑户型数据 → 改房间顶点、墙矩形或门窗 → 校验并应用。家具仍使用原有拖动/旋转/尺寸编辑交互。几何和家具修改都可撤销。该版本尚未提供墙体顶点的鼠标拖动建模工具。

## 图片还原扩展

像素观测与 `placement` 贴墙约束见 [pixel-observations.md](pixel-observations.md)。新增 `ottoman`（无靠背脚凳）和 `endtable`（方形边几），避免把脚凳误映射成带靠背单人沙发。

房间可选 `floorRotation`（度）、`floorColor`（#RRGGBB，3D材质色调）；家具可选 `accentColor`、`frameColor`、`pillowColor`。这些字段描述视觉近似，不代表精确家具资产。

构建时通过 `--reference-image` 嵌入 PNG/JPEG/WebP 原图；需要 `reference` 中的 width/height/originPx/mmPerPixel 完整标定。不要把文件绝对路径当作网页可访问的图片 URL。
