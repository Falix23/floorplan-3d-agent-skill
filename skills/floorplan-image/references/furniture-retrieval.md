# 按照片检索近似家具模型

用于把心仪家具照片中的可见结构匹配到可合法使用的现成网格。Agent负责识别、有限候选比较和适配决策；打包、替换与实际页面验收见 [家具照片指南](furniture-image.md)。检索是模型来源，不是照片重建或全网自动向量检索。

## 由图像确定筛选条件

先实际看照片，写出类别与可见结构。办公椅可描述为高靠背、独立头枕、软包座面、双扶手、气杆、五爪带脚轮底座；同时按可见材质分区记录代表色、取色区域/色卡、宽深高的依据和遮挡。优先匹配功能与结构，再比较轮廓比例；几何选型后必须适配可确认的主要配色，不能把库款深浅、色相明显不同只列为差异就完成交付。文字标签相同不等于形状相近，颜色接近也不能弥补关键结构缺失。

用结构关键词查作者或模型库的原始页面。先用公开的类别描述搜索；本地照片无需上传到外部网站。只有用户授权相关服务处理照片时才使用外部图片搜索。当前用Agent已有视觉能力、结构关键词、目录元数据和候选多视图完成筛选，不额外启动本地视觉、嵌入或图生3D推理模型。记录实际搜索和视觉筛选过程，不把人工选型说成自动向量检索。

## 手机随拍输入

- 保留完整原画面与哈希，用目标编号/位置明确对应要替换的家具；局部裁切仅作观察辅助，不替代原图或混淆同画面中的其他对象。
- 来源页标注的手机型号与本地EXIF分开记录，不能把前者冒充下载文件内的证据。仅摘录Make、Model、Orientation、焦距等必要字段，不输出或复制GPS、完整MakerNote；缺型号不猜。
- 透视缩短、相机倾斜不能直接变成资产倾斜。衣物、桌布、床品褶皱和阴影不当作刚性结构或尺寸标尺；尺度另需产品规格、用户尺寸或明确估计。
- 可见特征与隐藏部件分别写明，只比较实际查过的有限候选。严重遮挡或关键结构明确不符时不硬替换，保留原家具并报告缺口，可另展示大类近似候选。

## 核对可用性后再选资产

- 记录每个候选的原始页面、作者、明确许可、下载是否成功和主要差异。优先可适配并可随HTML/JSON携带的CC0或许可适合的资产，不能仅因“免费”“可下载”就认定允许再分发。
- 模型库、导入工具或项目本身的开源许可不自动覆盖每个模型。保留本次选中资产的许可页面/声明证据；涉及署名的许可还需在交付页面保留作者、源链接、许可链接及改动说明，仅埋入JSON元数据不够。
- 页面改版、失效、当前许可冲突、需要未获得的下载权限时如实记为不可用或待核实；不绕过登录限制，不用聚合站转述替代缺失的原始依据。
- 实际下载后查看模型多视图、部件与材质。检查轮脚/扶手等是否完整、有无无关房间/地板、外部纹理是否齐全、上轴/正面是否正确。合法的分离轮子或机械零件可以是多个连通分件；不能仅按连通分量总数判断断裂。

从少量可用候选中选择结构最接近的一项，说明取舍；不用“全库最优”描述有限搜索。缺少独立头枕、扶手形状不同、网背替代软包等重要差异必须保留，不能为了匹配照片默默加造部件。没有合适候选时报告缺口，展示可用候选及差异，或请求用户提供网格/产品规格；不自动部署或运行图生3D模型。

将目标实例、原图/模型哈希、可见特征、未知项、候选来源/许可和取舍另存为识别/匹配记录，或写入资产 `provenance`。替换清单只表达 `replace`/`keep` 决策与显式参数变更，契约和预检命令见 [家具照片指南](furniture-image.md#接入指定家具)；不要把事务脚本描述成自动识图或全网匹配器。

## 适配与接入

保留下载原件；改色、材质简化、网格简化另存。默认跟随照片可见材质的主要配色，用户明确要求保留库款配色时记录该要求。蓝色软垫与灰扶手等外观适配应以实际材质边界映射，不能将整把椅子染成一种颜色来声称匹配。用 `furniture_assets.py materials` 枚举材质，再按 [照片配色与分材质映射](furniture-image.md#照片配色与分材质映射) 准备 `--material-overrides`；导出后重新枚举，不能盲用旧索引。源材质把不同部件混在一起、或照片因遮挡/偏色无法确认本色时，报告分区或颜色缺口，保留可复核状态，不把未知颜色伪装成匹配完成。改几何时要说明改了什么，不能称原库资产自带该形状。

库模型的标注尺寸属于该库模型，并不是照片中实物的测量值。实际替换默认保留目标家具的位置、朝向和占地；若演示需要保持原网格比例，明确声明统一的工作尺度与估计依据，并同步更新宽深高，不能逐轴拉伸来掩盖形态差异。

在资产 `provenance` 记录这类信息，再用现有 `prepare` 的 `--provenance-json` 携带：

```json
{
  "inferencePerformed": false,
  "assetSource": {
    "kind": "library_retrieval",
    "title": "实际模型名",
    "author": "实际作者",
    "sourceUrl": "本次核对的原始页面URL",
    "license": "本次核对的许可",
    "licenseEvidence": "许可声明的来源与核对日期"
  },
  "selection": {
    "method": "结构关键词搜索与Agent多视图复核",
    "matchedFeatures": ["实际匹配的特征"],
    "differences": ["实际未匹配的特征"]
  },
  "adaptations": ["本次实际执行的改动；未改动时用空数组"]
}
```

运行 `furniture_assets.py prepare` 时将 `--method` 设为 `library-retrieval` 或如实描述本次适配，`--license` 填资产许可，`--source-image` 仍指用户照片用于哈希追溯。不要写成TripoSR/TripoSG推理。完整命令见 [家具照片与自定义模型](furniture-image.md)；不需要另跑图生3D后端。

已有PBR的库模型优先使用 `prepare --material-mode preserve-pbr --texture-max-size 256`，在此基础上按材质适配照片颜色，保留UV、法线、未选材质及必要纹理；保留纹理不等于必须保留库款原色。纹理缩放与配色改动须分别记录，并实际检查体积、外观和保存配额。默认顶点色模式可能造成稀疏三角形色块，不能把这种管线损失当作源资产缺陷。最终GLB与2D俯视图使用同一处理后几何与配色；2D颜色采样图不具备3D完整材质光照。参数和命令见家具照片指南。

## 验收与交付

在实际HTML检查相同资产的2D与3D、中心/尺寸/朝向、轮脚与座面的可见关系及分材质配色，并执行编辑、完整JSON导出重导入和刷新。以正面、侧面、斜视和俯视检查结构，用照片分区和色样核对主体颜色、明暗关系及未选材质，不能用漂亮的单个镜头掩盖缺陷。照片白平衡、光照和反光未知时保留不确定性，颜色接近不代表皮革、布料或木纹已精确恢复。与已有历史结果比较时使用相同尺度依据、相机和照明，不启动新的模型推理，注明已有手工修复或材质适配，不能把比较结果推广为所有家具的一般结论。

交付选中模型的来源、许可与明确造型差异，以及实际HTML和截图。照片与新资产的公开提交、上传、发布继续按用户当次授权；查询或下载资产本身不构成公开发布授权。

## 形状变化对照

直排→L形、方桌→圆桌必须出现真实网格轮廓变化；改色、改类型标签或换贴图不能单独算成功。替换前保持原形，不能把直排沙发加深、拉伸到L形外包来凑同尺寸。两版固定相机投影、位置与缩放、照明和墙剖切。

沙发保持同一背墙接触关系，检查实际L座面的空位、贵妃位左右方向；圆桌按原生比例统一缩放，方/圆桌同中心并使用相同名义外包 `w=d`，不逐轴拉伸隐藏比例差异。直排到L形属于形状改变对照，允许新模型自然增加进深，分别记录前后尺寸；下节同尺寸基线适用于同形近似替换，不覆盖本例外。

从实际HTML加载的网格按明确的台面/座面高度带取水平投影，记录圆台面边界与轮廓占比、L座面投影缺角及左右方向，并与配套2D核对；不能仅比较包围框或类型字段。输出前后截图、几何指标和取样依据；指标描述该HTML中的形状与2D/3D一致性，不是照片识别准确率。

## 多类家具替换到完整户型

按实例ID列出替换清单，逐件保留独立参考图、候选取舍与资产来源。不要把选中模型自带的渲染图当作独立输入来证明匹配。下层开放框架与完整搁板、两座垫与三座垫等结构差异需要实际多视图检查，不能只凭名称或正面轮廓判断。

先建立统一的对比基线，再接入资产。需要按模型原生比例调整工作占地时，保留原尺寸和依据，将相同的名义宽深、中心、朝向写入替换前后两版；尺度变化后重新计算床头/沙发背的贴墙位置。保留原生比例的统一缩放不等于照片尺寸测量；床整体包围宽也不是床垫宽。原参数模型若使用固定类别高度或部件超出名义范围，而自定义模型使用显式高度，需说明，不能声称两者实际包围体相同。源资产外围先接墙、背板自身缩进等情况，要区分原模型结构与轴向或放置错误。

在同一个完整户型中同时载入所有资产，核对墙、门窗、房间和非目标实例未因替换改变；检查实际占据轮廓的房间归属、墙/门、邻近家具和通行间距，包围框仅作提示。已有灶具/水槽与台面等叠放应逐对说明，不用全局包围框重叠数冒充质检结论。投影筛查不能代替完整3D或人体工学验证，演示中原有窄通道也不能称为推荐方案。

“不穿墙”不代表“没有家具干涉”。库餐桌变大后，要额外检查冰箱、衣柜和餐边柜等硬物，必要时核对真实网格而非仅看相机截图；桌布软包围与硬桌体分别记录，不能用软物/椅子常见叠放作借口忽略硬碰撞。放不下时保持原家具并报告适配缺口，或在明确标注的布局演示中先建立两版共用基线，逐项记录挪动对象；不能悄悄改布局来让照片匹配看似成功，也不能把窄通道演示当方案可行性通过。

整套方案一起执行编辑、撤销、全资产JSON导出、全新浏览器导入与刷新恢复，检查组合文件体积和实际浏览器保存结果。单件各自能缓存，不代表合并后仍在配额内。对比截图固定实际相机、照明和墙剖切，保留完整2D/3D原图与指定家具的局部前后图；只在展示排版层加标题或来源，不重画模型结果。原始资产、格式修正和材质适配分别保留；适配失败时继续保留原家具，不能以默认形状冒充资产已加载。
